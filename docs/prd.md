# PRD: PDF 요약 웹 앱

## 1. 개요

**한 줄 설명**: 대학생이 강의 자료나 논문 PDF를 올리면, AI가 핵심 내용을 한국어로 요약해 보여 주는 웹 앱.

**배경**: 대학생은 시험 공부와 과제 준비 중에 긴 강의 자료와 논문(특히 영어 원문)을 많이 읽어야 한다. 전체를 읽기 전에 "이 문서가 무엇을 말하는지"를 빠르게 파악할 수단이 필요하다.

**해결하려는 문제**
- 긴 문서에서 핵심 개념과 중요한 정의·공식을 찾는 데 시간이 많이 든다.
- 영어 논문·자료는 읽는 부담이 커서 내용 파악이 더디다.

## 2. 목표와 성공 기준

**목표**: 글자가 있는 PDF를 올리면 별도 가입 없이 바로, 공부에 쓸 수 있는 한국어 요약을 받는다.

**성공 기준 (이번 버전 완료 기준)**
1. **업로드 → 요약 흐름 동작**: 글자가 있는 PDF를 올리면 한 줄 요약, 핵심 개념 3~5개, 중요한 정의·공식이 한국어로 화면에 표시된다.
2. **오류 상황 안내**: 아래 상황에서 사용자가 이해할 수 있는 메시지가 나온다.
   - PDF가 아닌 파일을 올린 경우
   - 너무 큰 파일을 올린 경우
   - 글자가 없는(스캔) PDF를 올린 경우
   - AI 호출에 실패한 경우

> 응답 시간 목표와 모바일 대응은 이번 완료 기준에 포함하지 않는다. (5절 F3·F4 "있으면 좋음", 8절 열린 질문 참고)

## 3. 대상 사용자

- **주요 사용자**: 강의 자료나 논문 PDF를 읽어야 하는 대학생.
- **사용 상황**: 시험 공부나 과제 준비 중, 문서의 핵심 내용을 빨리 파악하고 싶을 때.
- 원문이 영어인 경우가 많으며, 사용자는 한국어 결과를 원한다.
- 계정 없이 바로 사용한다.

## 4. 사용자 요구 / 사용자 스토리

1. 대학생으로서, PDF를 올리고 요약을 바로 보고 싶다. 왜냐하면 전체를 읽기 전에 문서의 핵심을 빨리 파악하고 싶기 때문이다.
2. 대학생으로서, 한 줄 요약을 보고 싶다. 왜냐하면 이 자료가 내 공부나 과제에 필요한지 즉시 판단하고 싶기 때문이다.
3. 대학생으로서, 핵심 개념 3~5개를 보고 싶다. 왜냐하면 시험 공부의 중심 내용을 정리하는 출발점이 되기 때문이다.
4. 대학생으로서, 중요한 정의나 공식을 따로 보고 싶다. 왜냐하면 시험과 과제에서 정확히 알아야 하는 항목이기 때문이다.
5. 대학생으로서, 영어 원문도 한국어 요약으로 보고 싶다. 왜냐하면 영어 자료를 읽는 부담을 줄이고 싶기 때문이다.
6. 대학생으로서, 요약이 진행 중인지 알고 싶다. 왜냐하면 멈춘 것인지 기다려야 하는 것인지 알아야 하기 때문이다.
7. 대학생으로서, 문제가 생기면 이유와 다음에 할 일을 알고 싶다. 왜냐하면 잘못된 파일을 올렸을 때 스스로 해결하고 싶기 때문이다.
8. 대학생으로서, 가입 없이 바로 쓰고 싶다. 왜냐하면 급할 때 절차 없이 쓰고 싶기 때문이다.

## 5. 기능 명세

| 번호 | 기능 | 우선순위 |
|---|---|---|
| F1 | PDF 업로드 후 요약 보기 | 필수 |
| F2 | 진행 상태 표시와 오류 안내 | 필수 |
| F3 | 응답 시간 목표 | 있으면 좋음 |
| F4 | 모바일 화면 대응 | 있으면 좋음 |

### F1. PDF 업로드 후 요약 보기 (필수, 핵심 흐름)

**설명**: 사용자가 글자가 있는 PDF를 올리면 요약 화면에 다음을 한국어로 보여 준다.
- 한 줄 요약
- 핵심 개념 3~5개
- 중요한 정의나 공식
- 원문이 영어여도 결과는 항상 한국어로 표시한다.

**완료 조건**
- 글자가 있는 PDF를 올리면 위 세 항목이 모두 화면에 표시된다.
- 핵심 개념은 3개 이상 5개 이하로 표시된다.
- 영어 원문 PDF의 결과도 한국어로 표시된다.
- 회원가입·로그인 없이 사용할 수 있다.

### F2. 진행 상태 표시와 오류 안내 (필수)

**설명**: 요약하는 동안 진행 중임을 보여 주고, 문제가 생기면 이해하기 쉬운 메시지를 보여 준다.

**완료 조건**
- 요약 중에는 진행 중임을 알 수 있는 표시가 나온다.
- 다음 상황마다 원인과 다음에 할 일이 담긴 메시지가 나온다.
  - PDF가 아닌 파일
  - 너무 큰 파일
  - 글자가 없는(스캔) PDF: 처리하지 않고 안내만 한다.
  - AI 호출 실패

### F3. 응답 시간 목표 (있으면 좋음)
요약이 너무 오래 걸리지 않도록 목표 시간을 정한다. 구체적 기준은 정해지지 않았다(열린 질문).

### F4. 모바일 화면 대응 (있으면 좋음)
휴대폰에서도 업로드와 요약 보기가 편하게 되는 것. 이번 완료 기준에는 포함하지 않는다.

## 6. 범위 밖 항목 (이번 버전에서 하지 않음)

- 회원가입·로그인 (계정 없이 바로 사용)
- 요약 기록 저장 (지난 요약 목록 보관·다시 보기)
- 문서와 대화 (PDF 내용에 대해 AI에게 추가 질문하는 채팅)
- 스캔 PDF 글자 인식(OCR): 글자가 이미지로만 된 PDF는 처리하지 않고 안내만 한다.

## 7. 일정

구체적인 날짜는 정해지지 않았다. 마일스톤 순서와 담당 역할만 큰 단위로 정한다.

| 단계 | 목표 | 완료 조건 | 담당 역할 | 의존 관계 |
|---|---|---|---|---|
| M1. 설계 확정 | 열린 질문 중 파일 제한 등 설계 사항 결정 | 8절 열린 질문 중 설계 단계 항목에 답이 정해짐 | PM, 각 개발 역할 | 없음 |
| M2. 핵심 흐름 | 업로드 → 요약 표시 (F1) | 완료 기준 1 충족 | backend-developer, frontend-developer, ai-integration-specialist | M1 |
| M3. 진행 표시·오류 안내 | F2 구현 | 완료 기준 2 충족 | frontend-developer, backend-developer, ai-integration-specialist | M2 |
| M4. 검증 | 완료 기준 전체 확인 | 완료 기준 1, 2의 모든 상황을 확인함 | qa-engineer | M3 |
| M5. (선택) 있으면 좋음 | F3, F4 검토 | 열린 질문 답에 따라 결정 | frontend-developer 등 | M4 |

## 8. 위험 요소와 열린 질문

### 위험 요소
- **요약 품질**: 요약이 부정확하거나 정의·공식을 놓치면 시험 공부에 쓸 수 없다. 특히 공식은 글자 깨짐 위험이 있다.
- **긴 문서**: 매우 긴 PDF는 처리 시간이나 실패 가능성이 커질 수 있다. 파일 제한이 정해지지 않아 위험이 남아 있다.
- **스캔 PDF 이탈**: OCR을 하지 않으므로 스캔본 사용자는 쓸 수 없다. 안내 문구가 불친절하면 이탈로 이어진다.
- **AI 호출 실패**: 외부 호출 실패가 사용자 경험에 직접 영향을 준다.

### 열린 질문
1. 업로드할 수 있는 PDF의 최대 크기와 페이지 수는 얼마인가? (사용자가 아직 정하지 않음, 설계 단계에서 결정)
2. 응답 시간 목표를 정할 것인가? 정한다면 어느 정도인가?
3. 모바일 화면 대응을 이번 버전에 넣을 것인가?
4. 한 문서에 정의나 공식이 없거나 매우 많을 때 화면에 어떻게 보여 줄 것인가?
5. 업로드한 PDF와 요약 결과를 서비스가 얼마나 보관하는가? (기록 저장은 범위 밖이므로, 요약 후 즉시 삭제하는지 확인 필요)
6. 이용 제한(동시 사용량, 반복 업로드 제한 등)이 필요한가?
7. 일부만 글자가 있고 일부는 이미지인 PDF는 어떻게 처리할 것인가? (일부 요약 vs 스캔 PDF 안내)
8. 요약 결과를 복사하거나 내려받는 기능이 필요한가? (이번 범위에는 없음)
