# 설계: PDF 요약 웹 앱 (summary4pdf)

- 작성일: 2026-11-25
- 기준 문서: [docs/prd.md](../../prd.md)
- 상태: 사용자 검토 대기

이 문서는 PRD를 바탕으로 **어떻게 만들지**를 정한다. PRD와 이 문서가 다르면 이 문서가 최신 결정이다. 각 결정은 출처를 표시한다.

- **[사용자]**: 사용자가 직접 정한 것
- **[설계 판단]**: 대화에서 제안했고 사용자가 "이대로 진행"으로 받아들인 것
- **[빌더 재량]**: 구현하는 쪽이 정해도 되는 것

---

## 1. 목적과 배경

대학생이 강의 자료나 논문 PDF를 올리면, 핵심 내용을 한국어로 정리해 보여 주는 웹 앱이다. 시험 공부와 과제 준비를 할 때 문서 전체를 읽기 전에 "이 문서가 무엇을 말하는지" 빨리 파악하게 돕는다. 원문은 영어인 경우가 많다. **[사용자]**

## 2. 목표, 하지 않을 것, 실패로 보는 것

### 목표 (완료 기준, PRD 2절과 같음)
1. 글자가 있는 PDF를 올리면 한 줄 요약, 핵심 개념 3~5개, 정의·공식이 **한국어로** 화면에 표시된다.
2. PDF가 아닌 파일, 4MB를 넘는 파일, 글자가 없는(스캔) PDF, AI 호출 실패 때 사용자가 이해할 수 있는 안내가 나온다.

### 하지 않을 것 (PRD 6절)
- 회원가입·로그인
- 요약 기록 저장, 지난 요약 다시 보기
- 문서에 대해 AI에게 질문하는 채팅
- 스캔 PDF 글자 인식(OCR)
- 요약 결과 복사·내려받기 버튼 (PRD 열린 질문 8 → 넣지 않음) **[설계 판단]**
- 여러 파일 동시 업로드 **[설계 판단]**
- 앱 자체의 사용량 제한 (PRD 열린 질문 6 → 이번에는 두지 않음) **[설계 판단]**

### 실패로 보는 것 (기능은 돌아가도 안 되는 것)
- `OPENROUTER_API_KEY`가 브라우저로 전달되거나, 클라이언트 번들·응답·로그에 드러나는 것
- 영어 원문 PDF의 요약이 영어로 나오는 것
- 오류가 났을 때 화면이 멈추거나 빈 화면, 영어 원문 오류 메시지, 스택 트레이스만 보이는 것
- 올린 PDF나 추출한 텍스트가 서버의 디스크, DB, 로그에 남는 것

## 3. 제약 조건

| 항목 | 내용 | 출처 |
|---|---|---|
| 프레임워크 | Next.js (App Router), TypeScript | [사용자] Next.js / [빌더 재량] 버전·TS |
| 저장소 | GitHub `summary4pdf-ch7b` | [사용자] |
| 배포 | Vercel | [사용자] |
| 파일 크기 | PDF **최대 4MB**. 브라우저와 서버 양쪽에서 확인 | [사용자] 4MB / [설계 판단] 양쪽 확인 |
| 페이지 수 | 따로 제한하지 않음. 대신 AI에 보내는 텍스트 길이를 제한 | [설계 판단] |
| AI 호출 | OpenRouter. 1순위 `nvidia/nemotron-3-ultra-550b-a55b:free`, 실패 시 2순위 `nvidia/nemotron-3.5-super-vl:free` | [사용자] |
| API 키 | 서버에서 환경 변수 `OPENROUTER_API_KEY`로만 읽음. 로컬은 `.env`, 배포는 Vercel 환경 변수 | [사용자] |
| 언어 | 화면 문구, 결과, 오류 메시지 모두 한국어 | [사용자] |
| 보관 | PDF와 텍스트는 요청 처리 중 메모리에서만 다룸. 파일·DB·로그에 저장하지 않음 | [설계 판단] |

> 참고: Vercel 서버 함수는 요청 본문을 약 4.5MB까지만 받는다. 4MB 제한은 이 한도 안에 들어간다. multipart 오버헤드를 포함해도 넘지 않는지 구현 때 확인한다.

## 4. 전체 구조

```
[브라우저: 업로드 화면]
   │ 1) 파일 형식·크기 확인 (PDF, 4MB 이하)
   │ 2) multipart/form-data로 POST
   ▼
[Next.js 서버 API: POST /api/summarize]   ← Node.js 런타임
   ├─ 3) 크기·PDF 시그니처 재확인                         (backend-developer)
   ├─ 4) 텍스트 추출, 스캔 PDF 판단, 길이 자르기           (backend-developer)
   ├─ 5) OpenRouter 호출: 1순위 → 실패 시 2순위            (ai-integration-specialist)
   ├─ 6) 응답을 정해진 형태로 확인·정리                    (ai-integration-specialist)
   ▼
[브라우저: 결과 화면 또는 오류 안내]                       (frontend-developer)
```

- 요청은 한 번으로 끝난다(업로드부터 결과까지 하나의 HTTP 요청). 진행 단계 표시는 4.3절에 따른다.
- 서버 함수 최대 실행 시간(`maxDuration`)은 5절의 시간 한도가 들어가도록 설정한다. 값은 Vercel 요금제 한도 안에서 빌더가 정한다. **[빌더 재량]**

### 4.1 PDF 업로드와 텍스트 추출 (backend-developer)

- 받는 형식: `multipart/form-data`, 필드 이름 `file`, 파일 1개.
- 확인 순서:
  1. 파일이 없으면 → `NO_FILE`
  2. 4MB(4 × 1024 × 1024 바이트) 초과 → `FILE_TOO_LARGE`
  3. 파일 앞부분이 `%PDF-`로 시작하지 않으면 → `NOT_PDF` (확장자나 MIME만 믿지 않는다)
  4. 텍스트 추출에 실패하면(손상, 암호 걸린 PDF 등) → `PDF_UNREADABLE`
- 텍스트 추출은 서버리스 환경(Vercel Node.js)에서 동작하는 순수 JS 라이브러리를 쓴다. 라이브러리 선택은 빌더 재량이다. **[빌더 재량]**
- 페이지별로 텍스트를 뽑는다. 공백을 뺀 글자 수가 기준치보다 적은 페이지는 "글자 없는 페이지"로 본다. 기준치는 빌더가 정한다(예: 20자). **[빌더 재량]**
  - 모든 페이지가 글자 없는 페이지면 → `SCANNED_PDF` (요약하지 않음)
  - 일부만 글자 없는 페이지면 → 글자 있는 페이지만 요약하고 `skippedImagePages: true`를 넘긴다 (PRD 열린 질문 7) **[설계 판단]**
- AI에 보낼 텍스트는 최대 길이까지만 자른다. 잘렸으면 `truncated: true`를 넘긴다. 최대 길이는 두 모델 중 작은 쪽의 입력 한도에 맞춰 빌더가 정한다. **[빌더 재량]**
- 페이지 수(`pageCount`)와 파일 이름을 결과에 함께 넘긴다.

### 4.2 AI 요약 (ai-integration-specialist)

- OpenRouter Chat Completions API를 서버에서 호출한다. 키는 `process.env.OPENROUTER_API_KEY`에서 읽는다.
- **모델 전환 규칙** **[사용자]**
  1. 1순위 `nvidia/nemotron-3-ultra-550b-a55b:free`를 부른다.
  2. 다음 중 하나면 2순위 `nvidia/nemotron-3.5-super-vl:free`로 넘어간다.
     - 시간 한도 안에 응답이 없음 (5절)
     - HTTP 오류(4xx, 5xx, 호출 한도 초과 429 포함), 네트워크 오류
     - 응답은 왔지만 4.2의 결과 형태로 해석할 수 없음
     - 형태는 맞지만 한국어 결과가 아님: `oneLineSummary`와 핵심 개념 설명을 합친 글에서 한글 글자가 영문 글자보다 적으면 한국어가 아닌 것으로 본다. 영어 용어를 괄호로 붙이는 것은 허용되므로 기준은 넉넉하게 잡는다. **[설계 판단 — 빌더 점검 후 추가]**
  3. 2순위도 실패하면 → `AI_FAILED`. 두 모델 모두 429였으면 → `AI_RATE_LIMITED`.
- **모델 ID 확인** **[사용자]**: 구현을 시작할 때 실제 키로 두 모델을 각각 한 번씩 호출해 본다. 하나라도 없거나 호출되지 않으면 **작업을 멈추고 사용자에게 묻는다**. 이때 호출 가능한 무료 모델 후보를 함께 보여 준다. 에이전트가 마음대로 다른 모델로 바꾸지 않는다.
- 모델 ID 두 개는 코드 한 곳의 상수로 둔다. 무료 모델은 이름이 바뀌거나 사라질 수 있기 때문이다. 바꿀 때 그 상수만 고치면 되게 한다. **[설계 판단]**
- 두 번째 모델로 넘어간 사실은 사용자 화면에 따로 알리지 않는다. **[설계 판단]**
- **결과 형태** (AI에 JSON으로 답하게 하고, 서버에서 확인한다)

  ```json
  {
    "oneLineSummary": "문서 전체를 한 문장으로 (한국어)",
    "keyConcepts": [
      { "name": "개념 이름", "explanation": "한두 문장 설명" }
    ],
    "definitions": [
      { "term": "용어 또는 공식 이름", "description": "정의 또는 공식 내용" }
    ]
  }
  ```

  - `keyConcepts`: 3개 이상 5개 이하. 문서가 너무 짧아 3개가 안 되면 있는 만큼 허용하되, 1개 이상이어야 한다. 5개를 넘으면 앞 5개만 쓴다.
  - `definitions`: 0개 이상, 최대 8개. 넘으면 앞 8개만 쓴다 (PRD 열린 질문 4) **[설계 판단]**
  - 공식은 수식 렌더링 없이 글자 그대로 적는다 (예: `E = mc^2`). **[설계 판단]**
  - 모든 글은 한국어로 쓰게 지시한다. 전문 용어는 `한국어(English)`처럼 원어를 괄호로 붙여도 된다. **[설계 판단]**
- JSON 모드(`response_format`) 지원 여부는 모델마다 다를 수 있다. 지원하지 않으면 프롬프트로 JSON을 요구하고, 응답에서 JSON 부분을 찾아 해석한다. **[빌더 재량]**
- 프롬프트 문구, temperature 등 세부 값은 빌더 재량이다. **[빌더 재량]**

### 4.3 화면 (frontend-developer)

한 페이지짜리 앱이다. 모든 문구는 한국어다. **[설계 판단]**

**업로드 전**
- 맨 위: 앱 이름과 한 줄 설명(예: "강의 자료나 논문 PDF를 올리면 핵심을 한국어로 정리해 드려요").
- 가운데: 끌어다 놓는 큰 업로드 영역. 클릭하면 파일 선택 창이 열린다. 키보드(Tab, Enter/Space)로도 열 수 있어야 한다.
- 영역 아래: "PDF만, 최대 4MB".
- 그 아래 작은 글씨로 고지: "올린 문서는 요약을 위해 외부 AI 서비스로 전송돼요." **[사용자]**
- 파일을 고르면 서버로 보내기 전에 형식과 크기를 확인한다. 문제가 있으면 바로 안내하고 보내지 않는다.

**요약하는 동안**
- 로딩 표시와 함께 지금 단계를 문장으로 보여 준다: "PDF를 올리는 중" → "텍스트를 읽는 중" → "AI가 요약하는 중".
- 요청이 하나라서 서버의 실제 단계를 알 수 없다. 업로드가 끝나면 "텍스트를 읽는 중", 몇 초 뒤 "AI가 요약하는 중"으로 바꾸는 식의 추정 표시로 충분하다. **[빌더 재량]**
- 요약하는 동안 업로드 영역은 막는다(중복 요청 방지).

**결과 화면** (위에서 아래 순서)
1. 파일 이름, 페이지 수
2. 알림(해당될 때만):
   - `truncated`: "문서가 길어서 앞부분 위주로 요약했어요"
   - `skippedImagePages`: "이미지로 된 페이지는 제외하고 요약했어요"
3. **한 줄 요약**: 가장 크게 강조
4. **핵심 개념**: 번호 목록, 개념 이름 + 설명
5. **정의·공식**: "용어: 설명" 목록. 비어 있으면 "이 문서에서는 따로 정리할 정의나 공식을 찾지 못했어요"
6. "다른 PDF 요약하기" 버튼: 처음 화면으로 돌아간다

**기타**
- 휴대폰 화면 폭에서도 깨지지 않게 기본적인 반응형으로 만든다. 완료 기준에는 넣지 않는다. **[설계 판단]**
- 결과는 화면에만 있고, 새로고침하면 사라진다.
- 스타일링 방식(Tailwind CSS 등)은 빌더 재량이다. **[빌더 재량]**

### 4.4 API 응답 형식

`POST /api/summarize`

**성공 (200)**
```json
{
  "ok": true,
  "fileName": "lecture03.pdf",
  "pageCount": 24,
  "truncated": false,
  "skippedImagePages": false,
  "summary": { "oneLineSummary": "...", "keyConcepts": [], "definitions": [] }
}
```

**실패**
```json
{ "ok": false, "code": "FILE_TOO_LARGE", "message": "파일이 4MB를 넘어요. 더 작은 PDF로 다시 올려 주세요." }
```

| code | HTTP | 화면 메시지 (원인 + 다음에 할 일) |
|---|---|---|
| `NO_FILE` | 400 | 파일이 선택되지 않았어요. PDF를 끌어다 놓거나 눌러서 골라 주세요. |
| `NOT_PDF` | 415 | PDF 파일만 올릴 수 있어요. 파일 형식을 확인해 주세요. |
| `FILE_TOO_LARGE` | 413 | 파일이 4MB를 넘어요. 더 작은 PDF로 다시 올려 주세요. |
| `PDF_UNREADABLE` | 422 | PDF를 열 수 없어요. 파일이 손상되었거나 암호가 걸려 있는지 확인해 주세요. |
| `SCANNED_PDF` | 422 | 글자를 읽을 수 없는 PDF예요. 스캔한 이미지로 된 PDF는 아직 요약할 수 없어요. |
| `AI_RATE_LIMITED` | 429 | 지금 요청이 많아요. 잠시 후 다시 시도해 주세요. |
| `AI_FAILED` | 502 | 요약을 만들지 못했어요. 잠시 후 다시 시도해 주세요. |
| `INTERNAL_ERROR` | 500 | 알 수 없는 문제가 생겼어요. 잠시 후 다시 시도해 주세요. |

- 메시지 문구는 서버가 정해서 보내고, 화면은 그대로 보여 준다. 브라우저에서 먼저 거른 경우(`NOT_PDF`, `FILE_TOO_LARGE`)는 같은 문구를 화면에서 바로 쓴다.
- 서버나 Vercel이 JSON이 아닌 응답(예: 시간 초과 504, 플랫폼의 413)을 돌려줘도 화면은 `AI_FAILED` 또는 알맞은 안내로 처리한다. 빈 화면이 되면 안 된다.

## 5. 시간 한도 **[설계 판단]**

- 모델 하나당 응답 대기 한도: 약 60초. 넘으면 그 호출을 끊고 다음 모델로 넘어간다.
- 전체 요청은 "추출 시간 + 두 모델 대기 시간"이 서버 함수 최대 실행 시간 안에 들어가야 한다. Vercel 요금제 한도가 이보다 짧으면 모델당 한도를 줄여서 맞춘다. **[빌더 재량]**
- 응답 시간 목표는 완료 기준이 아니다 (PRD 열린 질문 2).

## 6. 보안과 개인정보 **[설계 판단]**

- `OPENROUTER_API_KEY`는 서버 코드에서만 읽는다. `NEXT_PUBLIC_` 접두사를 붙이지 않는다.
- 키가 없으면 서버는 `INTERNAL_ERROR`로 응답하고, 서버 로그에는 "키가 설정되지 않음"만 남긴다. 키 값은 어디에도 출력하지 않는다.
- PDF 바이트와 추출 텍스트는 디스크(`/tmp` 포함)나 DB에 쓰지 않는다. 로그에는 파일 크기, 페이지 수, 사용 모델, 오류 코드, 소요 시간만 남긴다.
- **외부 제공자** **[사용자]**: OpenRouter 무료 모델은 제공자가 입력 내용을 기록하거나 학습에 쓸 수 있다. 사용자는 이를 받아들였다. 위 "남기지 않음"은 우리 서버에만 해당한다. 화면에는 4.3절의 고지를 넣는다. 무료 모델 호출에 필요한 OpenRouter 계정의 개인정보(데이터 정책) 설정은 사용자가 직접 확인한다.
- `.env*` 파일은 `.gitignore`에 넣어 저장소에 올라가지 않게 한다. 대신 변수 이름만 적은 `.env.example`을 둔다.
- 프로젝트 규칙: 에이전트는 `.env*` 파일을 열거나 값을 출력하지 않는다.

## 8. 시험할 상황 (qa-engineer)

자동 시험(단위 시험)과 실제 실행 확인을 함께 한다. 실제 OpenRouter 호출이 필요한 시험은 키가 있을 때만 돌고, 나머지는 AI 호출을 가짜로 바꿔서 시험한다.

| # | 상황 | 기대 결과 |
|---|---|---|
| 1 | 글자가 있는 한국어 PDF | 세 항목이 한국어로 표시됨 |
| 2 | 영어 논문 PDF | 결과가 한국어 |
| 3 | 4MB 초과 PDF | 화면에서 바로 `FILE_TOO_LARGE` 안내, 서버 요청 없음 |
| 4 | 서버에 4MB 초과 요청을 직접 보냄 | 413 `FILE_TOO_LARGE` |
| 5 | 확장자만 .pdf인 다른 파일 | `NOT_PDF` |
| 6 | 스캔(이미지) PDF | `SCANNED_PDF` |
| 7 | 일부 페이지만 이미지인 PDF | 요약 + "이미지 페이지 제외" 알림 |
| 8 | 손상·암호 PDF | `PDF_UNREADABLE` |
| 9 | 아주 긴 PDF | 요약 + "앞부분 위주" 알림 |
| 10 | 1순위 모델 오류·시간 초과 (가짜) | 2순위 모델 결과로 정상 표시 |
| 11 | 두 모델 모두 실패 (가짜) | `AI_FAILED` 안내 |
| 12 | 두 모델 모두 429 (가짜) | `AI_RATE_LIMITED` 안내 |
| 13 | AI가 형식이 틀린 답을 줌 (가짜) | 다음 모델로 넘어감, 둘 다면 `AI_FAILED` |
| 14 | 정의·공식이 없는 문서 | 빈 상태 문구 표시 |
| 15 | 키가 클라이언트에 노출되지 않음 | 빌드 결과물과 응답에 키 문자열 없음 |

시험용 PDF는 시험 코드가 직접 만들거나 저장소의 시험 폴더에 작은 파일로 둔다. **[빌더 재량]**

## 11. 남은 위험

- **무료 모델의 변동**: 무료 모델은 이름이 바뀌거나 사라지고, 호출 한도가 낮다. 설계 중 공개 모델 목록으로 두 ID를 확인하려 했지만 확실한 결과를 얻지 못했다. 구현 때 실제 키로 두 모델이 호출되는지 가장 먼저 확인하고, 안 되면 사용자에게 묻는다(4.2).
- **요약 품질**: 무료 모델의 한국어 품질과 JSON 형식 준수가 기대보다 낮을 수 있다. 형식이 틀리면 다음 모델로 넘어가게 해서 줄인다.
- **실행 시간**: 두 모델이 모두 느리면 Vercel 함수 시간 한도에 걸릴 수 있다. 5절의 시간 한도로 대응한다.
